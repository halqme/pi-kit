# 運用チェックリスト

## 契約

- `name` と `description` が対象と利用タイミングを一意に示す
- 明示的なトリガーと、使わない条件がある
- 入力、出力、終了条件が追跡できる

## 実行

- 決定的な処理はスクリプトへ分離されている
- スクリプトは終了コードを使い分け、標準エラーに診断情報を出す
- リトライ、タイムアウト、冪等性、部分成功を必要に応じて定義している
- 認証情報や個人情報をログ・引数・成果物に残さない

## 境界

- 曖昧な対象、空入力、巨大入力、権限不足、外部障害を扱う
- 破壊的・外部公開の操作には確認ゲートがある
- 失敗時に途中状態、再実行方法、復旧手順が分かる

## 保守

- 詳細 API は `references/`、固定ファイルは `assets/` に置く
- スクリプト単体で正常系と代表的な異常系を検証できる
- `SKILL.md` には実行順序と参照先だけを残す
